# Календарь мероприятий HEMA

[![CI](https://github.com/AlexanderBalenko/hema-calendar/actions/workflows/ci.yml/badge.svg)](https://github.com/AlexanderBalenko/hema-calendar/actions/workflows/ci.yml)
[![Pages](https://github.com/AlexanderBalenko/hema-calendar/actions/workflows/pages.yml/badge.svg)](https://github.com/AlexanderBalenko/hema-calendar/actions/workflows/pages.yml)

Календарь мероприятий по историческому фехтованию — турниры, фестивали, лагеря, семинары и
лекции: прошедшие и будущие, с фильтрами по типу, оружию, региону, городу и датам. Сайт — статический, **сервера у него нет вовсе**.

Турниры лежат файлами в этом репозитории (`data/events/`), сайт собирается из них и
публикуется на GitHub Pages. Отсюда всё остальное: база не нужна, правки видны в истории git,
а модерация — это слияние ветки, в которую импорт складывает заявки.

Источник правды для турниров — **база портала hema.ru**: клубы-организаторы, города и номинации
там размечены руками, и календарь их переносит (`scripts/import_portal.py`), а не добывает
заново. Почему так — `docs/Calendar.md` §3а.

Чего здесь нет намеренно: учётных записей и входа, клубов, результатов турниров и медалей,
личных отметок «пойду/интересно». Календарь не знает, кто его читает, и не хранит ничьих
персональных данных.

## Состав

| Каталог | Что это |
|---|---|
| `data/` | **Источник правды**: турниры по файлу на турнир, справочники городов и оружия. Формат — `docs/Data.md`. |
| `frontend/` | Next.js 14, статическая сборка (`output: 'export'`). Лента недель, сетка месяца, список, фильтры, страницы турниров. Оформление перенесено из портала hema.ru. |
| `scripts/` | Проверка данных, сборка JSON для сайта, импорты из внешних источников. |
| `e2e/` | Браузерный смоук против собранного сайта. |
| `docs/` | Решения и правила — `docs/Calendar.md`, формат данных — `docs/Data.md`. |

## Запуск

```bash
pip install pyyaml
python scripts/build_json.py          # data/*.yaml → frontend/src/generated/*.json
cd frontend && npm ci && npm run dev  # http://localhost:3000
```

Сборка статики — `npm run build`, результат в `frontend/out`; посмотреть его можно любой
раздачей статики, например `python -m http.server 3003` из этого каталога.

## Данные

Один турнир — один файл, имя файла и есть адрес страницы:

```yaml
# data/events/2026/saber-meister-2026.yaml
title: Saber Meister
starts: 2026-11-07
city: Калуга
organizer: Дружина «Рысь»
url: https://vk.ru/club240902116
nominations:
  - weapon: saber
    gender: female
```

Полный формат и правила — `docs/Data.md`. Проверка:

```bash
python scripts/validate_data.py            # ошибки ломают прогон
python scripts/validate_data.py --strict   # и предупреждения тоже
```

Это тот самый гейт, которым раньше была очередь модерации. Он стоит в двух местах: импорт не
пушит в `main` то, что не прошло проверку, а кривую заявку видно в ветке до слияния.

## Как это выглядит

Оформление — портальное: те же токены цвета, шрифты (Playfair Display + Inter), шкала
размеров, шапка и календарная сетка. Главный вид — лента недель, как на hema.ru; рядом сетка
месяца и плотный список. Фильтры тоже портальные, включая критерии участника (возраст, пол,
смешанные номинации) и глазик «неподходящие», который показывает не прошедшие фильтр турниры
неактивными и с причиной — `docs/Calendar.md` §5б. Чего нет и не будет: отметок «пойду»/«был»,
медалей и результатов — календарь не знает, кто его читает.

## Как добавить турнир

- **В портале.** Основной путь: турнир заводится на hema.ru, в календарь приезжает переносом
  `python scripts/import_portal.py` (нужна поднятая база портала).
- **Формой.** Кнопка «Анонсировать мероприятие» на сайте ведёт в Google-форму; раз в сутки импорт
  складывает новые ответы в ветку `submissions`, и в календарь они попадают, когда вы её
  вольёте. Заявителю не нужны ни аккаунт GitHub, ни git. Завести форму — пять шагов в
  `scripts/google-form/README.md` (скрипт создаёт её сам).
- **Правкой репозитория.** Добавить файл в `data/events/<год>/` — хоть прямо в вебе GitHub,
  коммитом или пул-реквестом.
- **Импортом.** `scripts/import_hemagon.py` (прошедшие турниры) и
  `scripts/import_spreadsheet.py` (анонсы из таблиц) пишут те же файлы; по расписанию их
  запускает `.github/workflows/import.yml`: машинное уезжает прямо в `main` и сразу на сайт,
  заявки ждут вас в ветке.

Повторный прогон любого импорта не плодит дублей: своё он узнаёт по паре «источник + ключ», а
чужое похожее — по сверке «тот же день, то же место, похожее название».

## Тесты

```bash
python scripts/validate_data.py        # данные

# юнит-тесты фронта (раскладка месяца, разбор адреса, отбор турниров)
docker run --rm -v "$(pwd)/frontend:/app" -w /app node:22-alpine \
  node --experimental-strip-types --test "src/**/*.test.ts"

# браузерный смоук по собранному сайту (нужен frontend/out)
sh scripts/e2e-smoke.sh
```

Полный прогон на каждый push делает `.github/workflows/ci.yml`; публикация
(`.github/workflows/pages.yml`) не стартует без его зелёного результата.

## Публикация

Сборка и выкладка — GitHub Pages через Actions. Адрес не зашит в код: подкаталог и домен
workflow берёт из настроек Pages, поэтому тот же репозиторий работает и на `*.github.io`
(в подкаталоге `/hema-calendar`), и на своём домене `calendar.hema.ru` — в корне.

**Свой домен** включается в три шага и строго в этом порядке.

1. В DNS `hema.ru` — запись `calendar` типа CNAME на `alexanderbalenko.github.io.` (точка на
   конце обязательна). Дождаться, пока её начнут отдавать сами серверы зоны: `nslookup
   calendar.hema.ru ns1.reg.ru`.
2. **Settings → Pages → Custom domain** в репозитории: вписать `calendar.hema.ru` и сохранить.
   Именно здесь, а не файлом: файл `CNAME` в сборке переключает домен только при публикации
   **из ветки**, а календарь публикуется из workflow — тогда GitHub этот файл не читает.
   Файл в `frontend/public/CNAME` всё равно лежит: он не мешает и пригодится, если публикацию
   когда-нибудь переведут на ветку.
3. Собрать заново. Подкаталог приходит из настроек Pages на сборке (`base_path` у
   `actions/configure-pages`), и сборка, сделанная до шага 2, несёт в адресах `/hema-calendar`.

Порядок не ради порядка: пункт 2 до пункта 1 уведёт с `*.github.io` на адрес, которого ещё нет
в DNS, и сайт станет недоступен обоими адресами сразу.

**Переменные репозитория** (Settings → Secrets and variables → Actions → Variables) —
всё, что нельзя или не нужно держать в коде:

| переменная | зачем |
|---|---|
| `SUBMIT_FORM_URL` | адрес Google-формы для кнопки «Анонсировать мероприятие» |
| `FORM_SHEET_ID`, `FORM_SHEET_GID` | таблица ответов формы, откуда импорт берёт заявки |
| `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_GID` | таблица организаторов с анонсами |
| `METRIKA_ID` | номер счётчика Яндекс.Метрики |

Каждая необязательна. Нет `METRIKA_ID` — счётчик не собирается в страницу вовсе, ни скрипта,
ни куки; так он и выключается. Вебвизор не включён намеренно: календарь не хранит о читателе
ничего, и запись сеансов этому противоречит первой.

## Чего ещё нет

- карты турниров и подписки на фильтр — обсуждалось, не решено.
