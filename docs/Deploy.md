# Выкладка календаря

Что подготовлено, как разворачивать и что **ещё не проверено живьём** — сервера под календарь
на 05.11.2026 нет, поэтому ниже описан готовый, но не исполненный путь.

## 1. Из чего состоит

| Что | Где | Зачем |
|---|---|---|
| `deploy/prod/docker-compose.yml` | на сервере в `/opt/hema-calendar/` | три контейнера: база, API, фронт |
| `deploy/prod/.env.example` | рядом, под именем `.env` | секреты и тег образа; в репозиторий не едет |
| `deploy/caddy/Caddyfile` | у Caddy | одно имя `calendar.hema.ru`, TLS автоматом |
| `.github/workflows/ci.yml` | GitHub | полный прогон пирамиды |
| `.github/workflows/deploy.yml` | GitHub | кнопка выкладки, `needs: tests` |

Наружу смотрит **только фронт**. API своего домена не имеет: браузер ходит на свой origin
(`/api/…`), и запрос проводит сам фронт (`frontend/app/api/[...path]/route.ts`). Отсюда три
следствия:

- нет CORS и нет второго сертификата;
- порт бэкенда не публикуется вовсе;
- адрес посетителя доезжает до лимитера заявок цепочкой `Caddy → фронт → бэкенд` через
  `X-Forwarded-For`, поэтому у бэкенда включён `Proxy__Enabled=true`. Снять его — значит
  посчитать весь интернет одним посетителем и выдать всем вместе пять заявок в час.

## 2. Первый разворот

```sh
# на сервере
mkdir -p /opt/hema-calendar && cd /opt/hema-calendar
# docker-compose.yml кладёт workflow; .env заполняется руками по .env.example
openssl rand -hex 24     # ключ модератора: ТОЛЬКО латиница и цифры
openssl rand -base64 24  # пароль базы
```

Ключ модератора обязан быть латиницей: значение заголовка HTTP не принимает кириллицу, и
браузер падает ещё до отправки запроса (экран модерации это объясняет словами, но работать с
таким ключом всё равно нельзя).

Дальше — кнопка **Deploy calendar.hema.ru** во вкладке Actions. Она соберёт образы, накатит
схему и поднимет контейнеры; без зелёного CI кнопка не сработает.

## 3. Наполнение данными

Пустой календарь никому не нужен, поэтому сразу после первого разворота:

```sh
export CALENDAR_API=https://calendar.hema.ru CALENDAR_ADMIN_KEY=<ключ из .env>
python scripts/seed_directories.py        # 195 городов, 13 видов оружия
python scripts/import_hemagon.py          # прошедшие турниры (330 записей)
python scripts/import_spreadsheet.py --google <id> --gid <gid>   # анонсы организаторов
python scripts/import_spreadsheet.py --xlsx <график.xlsx>
```

Все импорты идемпотентны: повторный прогон обновляет записи и не создаёт новых. Порядок важен
только для справочников — без них города и оружие приедут строками.

`scripts/seed_demo_events.py` на бою **не запускать**: это выдуманные турниры для пустого стенда
и для CI.

## 4. Обновление версии

Выкладка не трогает схему сама по себе: workflow сначала собирает пакет миграций
(`dotnet ef migrations bundle`), везёт его на сервер и применяет, и только потом поднимает новые
образы. Приложение миграции не применяет никогда — иначе любой перезапуск контейнера менял бы
боевую схему.

Откат: `IMAGE_TAG` в `.env` на предыдущий тег и `docker compose up -d`. Откат миграции —
отдельная операция руками (у каждой миграции обязан быть рабочий `Down`).

## 5. Резервная копия

База — единственное, чего нет больше нигде: заявки приходят от людей, а импорт восстановит
только то, что есть в источниках.

```sh
cd /opt/hema-calendar && set -a && . ./.env && set +a
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > /var/backups/calendar-$(date +%F).sql.gz
```

## 6. Чего ещё нет

- **Сервера.** VPS под календарь не создан; адрес, реестр образов и ключи доступа не заведены.
- **Проверки выкладки живьём.** Всё выше написано по работающему локальному стенду и по опыту
  портала, но ни один шаг на боевой машине не исполнялся.
- **Мониторинга.** Ни метрик, ни алертов: `/api/health` есть, но его никто не опрашивает.
- **Почты.** Заявителю не уходит ни подтверждения, ни отказа — контакт нужен, чтобы модератор
  написал сам.
